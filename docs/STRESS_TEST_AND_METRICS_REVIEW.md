# 压力测试、指标口径与待确认问题

**更新时间：2026-08-30**

## 一、评审结论

整体方向合理。网络波动、节点高负载和多节点冲突三类测试，能够覆盖赛题对实时性、弱网保持
和一致性的主要要求。当前最需要补的不是更多测试名称，而是固定每类测试的参数、样本、计时
边界、重复次数、ground truth 和计算公式，否则最后很容易出现“测过了，但结果不能用于答辩”。

## 二、建议测试矩阵

| 测试组 | 自变量 | 固定条件 | 主要输出 |
|---|---|---|---|
| 基础并发 | 并发 1/5/10/20，请求数至少 100 | 正常网络、同一模型、同一数据切片 | 成功率、吞吐、平均/P50/P95/P99、路由分布、正文流量 |
| 网络波动 | RTT 20/100/300/500ms，丢包 0/1/5/10%，抖动 0/20/50/100ms | 固定 workload 与并发 | deadline 达标率、基本业务保持率、上云/Peer/Fallback 比例 |
| 节点负载 | CPU/队列低、中、高；单节点宕机 | 固定网络与任务难度 | 路由变化、排队时间、失败率、恢复时间 |
| 多节点冲突 | 标签相反、动作相反、过期观测、低可靠节点、版本不一致 | 每例有 ground truth 与关联任务 ID | 原始冲突率、自主形成结果率、正确解决率、云复核率 |
| 双场景 | 工业视觉、交通监控 | 相同调度器和指标口径 | 两场景各自端到端时延、准确率/F1、保持率和资源占用 |

每组先预热，再至少重复 3 次；必须保存 commit、硬件、软件版本、配置、原始逐请求结果和聚合
脚本。`scripts/benchmark_system.py` 可以测并发和客户端时延，但网络故障仍需由 Toxiproxy 或
`tc-netem` 独立注入并记录。

## 三、需要调整或特别说明的指标

1. **平均端到端时延 ≤0.2s：**建议从客户端 POST 发出到完整响应体接收完毕，包含边缘预处理、
   排队、网络、远端推理和返回；同时报告 P95，避免平均值掩盖长尾。
2. **弱网基本业务保持率 ≥90%：**必须先按场景定义“基本功能”。例如工业至少返回安全等级和
   可执行动作，交通至少返回事件/拥堵状态；只返回 HTTP 200 不能算完成。
3. **冲突率 ≤5%：**应统计仲裁前原始冲突。如果统计仲裁后结果，算法天然会把冲突压到接近零，
   指标没有区分度。
4. **冲突解决成功率 ≥90%：**分母只能是带 ground truth 的冲突任务；当前系统中的
   `resolution_success` 只是“自主形成结果”，不能替代正确率。
5. **通信成本：**当前 runner 只计算请求/响应正文。正式报告还应注明是否包含 HTTP/TLS 头、
   重传、心跳和模型同步，至少保证各方案口径一致。
6. **单次推理内存 ≤1.5GB：**分别报告进程峰值 RSS、GPU 专用显存增量和模型文件大小，不能
   相互替代；还要明确基线和采样工具。
7. **TTFT 降低 75%：**边侧与云端必须使用相同输入、输出上限和冷/热启动条件，并确认是否
   包含网络、排队和分词。
8. **能力保持 80%--90%：**边侧/云端使用相同 GSM8K、HumanEval、C-Eval 子集、提示词、
   解码参数和评分脚本，再按同任务得分比计算。

## 四、实现难度判断

风险最高的是边侧真实模型同时满足 0.2s、1.5GB 和 80%--90% 能力保持率。这三个目标互相
牵制：减小模型和量化有利于时延/内存，却可能降低能力；当前一次 RSS 约 1.79GB、Adapter
测量约 17s，说明还不能把裸模型 174.45ms 当成系统达标证据。

第二个难点是多摄像头交通的 ground truth 与关联冲突。检测、跟踪、ReID、摄像头时间同步和
拓扑窗口任何一层都会引入误差，工作量显著大于合成 JSON。建议先冻结 2--4 个相邻摄像头的
小子集，建立可回放关联事件，再扩展。

第三个难点是真实负载和弱网复现。当前网络快照由请求 metadata 注入，负载/队列主要由环境
变量心跳上报，适合算法单元测试但不等于在线采样。正式实验需要采集真实 CPU、内存、队列和
RTT，并把故障配置与逐请求结果按时间对齐。

## 五、建议询问老师的三个问题

1. “平均端到端时延 ≤0.2s”的计时边界是否包含采集/预处理、排队、网络、云端推理和结果返回；
   工业与交通两个场景是否都必须分别达标？
2. “能力保持 80%--90%、TTFT 降低 75%、单次推理内存 ≤1.5GB”是否全部是强制项；云端
   满血模型由谁指定，内存按 RSS、显存增量、二者之和还是模型文件大小计算，TTFT 是否包含
   网络和冷启动？
3. “冲突率 ≤5%”指仲裁前原始冲突还是仲裁后的最终冲突；是否允许用人工构造的带真值冲突集，
   以及“解决成功”是否必须与真实标签一致？
