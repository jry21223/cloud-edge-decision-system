> 质量检测 + 多摄像头交通感知”，MIMII 未接入当前原型，也不作为本次实现完成项。工业视觉

**阶段结论：**在第一版“轻量边缘初筛 + 云端复核”思路的基础上，本阶段根据完整赛题指标，
将方案升级为面向工业视觉质量检测和多摄像头交通感知的双场景云边协同系统，并设计、实现了
DREAM-CE自适应路由与多边缘证据仲裁算法。目前算法骨架和单元测试已经完成，但工业视觉、
CityFlow真实感知模型以及0.2秒时延、90%弱网业务保持率、5%冲突率和90%仲裁成功率仍需
真实数据及部署实验验证，现阶段不能宣称已经达到比赛指标。

## 1. 本阶段任务定位

第一版调研主要围绕MobileNetV3-Small和ResNet18构建图像分类云边分流Demo，重点回答
“什么时候在边缘计算、什么时候交给云端”。在获得完整赛题要求后，原方案存在三个不足：

1. 只覆盖一个图像分类场景，不能满足“至少两类差异明显场景”的要求；
2. 只考虑EDGE和CLOUD，未完整覆盖Peer Edge协同、重叠感知冲突和云端仲裁；
3. 普通图像分类无法验证数学、代码、自然语言推理能力保持率及边侧大模型内存、TTFT指标。

因此，本阶段不再把通用图像分类作为最终主场景，而是将工作拆分为四层：

- 工业视觉质量检测；
- 多摄像头交通感知与跨节点关联；
- 边侧小模型与云端强模型动态协同；
- 多边缘冲突检测、证据融合与安全降级。

原MobileNetV3-Small/ResNet18方案仍可作为全边缘、全云端和固定分流的简单对照，但不作为
最终双场景方案的核心模型。

## 2. 测试集方向

### 1）历史候选：MIMII DUE 工业声学

早期调研曾建议选择MIMII DUE中的Fan和Pump两类设备，保留正常/异常样本以及source、
target domain。该数据可以验证设备异常检测、环境噪声变化和设备域偏移，适合模拟多个工业
边缘传感节点；当前主线已改为工业视觉，本节仅保留作备选方案记录。

建议边侧基线为：

```text
音频 → Log-Mel频谱 → 轻量AutoEncoder/嵌入模型
     → 异常分数 → 正常/预警/故障 → DREAM-CE路由
```

AI4I 2020可以用于前期CSV接口和调度链路冒烟，但因为它是合成表格数据，不建议作为最终工业
创新证据。

### 2）智慧交通：CityFlowV2

交通场景选择CityFlowV2中4至6个相邻摄像头、至少2个路口的子集。每个摄像头模拟一个边缘
节点，保留视频、时间戳、检测框、车辆ID、摄像头拓扑及同步信息。

建议算法链路为：

```text
车辆检测 → 单摄像头跟踪 → ReID特征
         → 摄像头拓扑/时间窗约束 → 跨摄像头轨迹关联
         → 多边缘冲突检测与DREAM-Fuse仲裁
```

当前工业视觉和交通视频在业务任务、场景拓扑和协同方式上仍有明显差异；最终是否满足“两类
差异明显场景”的口径需要老师确认。工业声学与交通视频的模态差异更强，但声学仅作为历史备选。

### 3）通用推理能力测试

应用场景数据不能证明边侧模型在数学、代码和自然语言推理上保持云端模型80%至90%的能力，
因此需要单独增加：

- GSM8K：数学推理；
- HumanEval：代码生成；
- C-Eval：中文知识与自然语言推理。

边侧和云端必须使用相同提示词、解码参数和评分方法，按下式计算：

```text
能力保持率 = 边侧模型得分 / 云端模型得分 × 100%
TTFT降幅 = (云端TTFT - 边侧TTFT) / 云端TTFT × 100%
```

### 4）网络和冲突压力集

在相同业务样本上人工注入20/100/300/500ms RTT、0%/1%/5%/10%丢包及5/10/30秒断网，
同时构造节点判断相反、时间戳过期、置信度失真和模型版本不一致等冲突样本。

## 3. 现有算法调研结论

现有研究已经覆盖了本项目的大部分单项能力，但没有一套算法可以直接同时满足本赛题全部
约束，因此适合采用“成熟基线 + 跨层联合改进”的方式。

| 模块 | 可复用现有方法 | 本项目采用方式 |
|---|---|---|
| 工业视觉质检 | YOLO系轻量检测器 / EfficientAD | 冻结一类工件与缺陷集合后完成边侧基线 |
| 工业声学（历史备选） | Log-Mel、AutoEncoder、Mahalanobis异常分数 | 当前不接入 |
| 交通感知 | 车辆检测、ByteTrack、ReID、匈牙利匹配 | 增加摄像头拓扑和时间窗约束 |
| 动态卸载 | Edgent、CoEdge | 扩展为EDGE/PEER/CLOUD/FALLBACK多路径选择 |
| 特征传输 | BottleNet++ | 后续用于压缩轨迹和中间特征，而非上传完整视频 |
| 边侧大模型 | AWQ/GGUF 4bit量化、知识蒸馏 | 控制内存并测量能力保持率 |
| 模型路由 | RouteLLM、选择性分类 | 根据不确定性、代价和风险选择边侧或云端模型 |
| 置信度处理 | Temperature Scaling | 避免直接把未校准Softmax当作正确概率 |
| 分布式训练 | FedAvg | 作为后续跨节点模型更新扩展，不是当前MVP前置依赖 |

本项目不将已有模块本身声明为创新。创新重点放在赛题约束下的统一路由目标、多边缘证据仲裁、
安全闭环以及可核验指标口径。

## 4. DREAM-CE创新算法

DREAM-CE全称为Deadline, Risk and Evidence-Aware Multi-edge Cloud-Edge，即面向截止时间、
风险和证据一致性的多边缘云边协同算法，由三个主要模块组成。

### 1）DREAM-Exit：动态本地退出

紧急事件或critical任务立即在本地执行安全动作。普通任务根据风险、网络退化和deadline压力
动态调整边缘接受阈值：

```text
T = clip(T_base + A_risk - 0.18D_network - 0.08P_deadline, 0.55, 0.95)
```

高风险任务提高阈值，要求更强证据；网络恶化或deadline即将耗尽时降低阈值，使更多任务留在
本地完成，从而提高弱网期间基本业务保持率。

### 2）DREAM-Route：多路径约束路由

系统为PEER_EDGE、CLOUD和EDGE_FALLBACK建立候选执行配置，统一计算：

```text
J(k) = L(k)/D
     + 2W_risk(1-Q(k))
     + 2.5(1-A(k))
     + 0.25Load(k)
     + 0.05Comm(k)
     + Penalty(k)
```

其中，`L(k)`为预计时延，`D`为剩余deadline，`Q(k)`为模型预期准确率或节点可靠度，`A(k)`
为路径可用率。超过deadline或远端不可用的候选受到硬惩罚。算法优先选择满足deadline且总代价
最小的路径，远端失败时在有限时间内返回保守本地结果。

### 3）DREAM-Fuse：多边缘证据仲裁

节点证据权重定义为：

```text
w_i = p_cal_i × reliability_i × freshness_i × topology_i × version_i
freshness_i = exp(-ln(2) × age_i / half_life)
```

其中，`p_cal_i`为校准置信度，`reliability_i`为节点历史可靠度，`freshness_i`惩罚旧观测，
`topology_i`表示交通拓扑/工业传感器一致性，`version_i`处理模型版本差异。支持相同决策的节点
证据相加形成共识分数。共识不足时请求云端复核，获得充分支持的高风险事件则立即执行保守安全
动作。

相较于“直接选择最高置信度节点”，DREAM-Fuse能够抑制过度自信、长期不可靠或观测过期的
节点，且可以解释每次仲裁的证据来源。

## 6. 实验评价指标

### 1）赛题硬指标

```text
平均端到端时延 = 所有任务端到端时延总和 / 任务总数
弱网业务保持率 = 网络异常期间完成基本功能的任务数 / 弱网任务总数
冲突率 = 产生矛盾结果的关联任务数 / 多节点关联任务总数
冲突解决成功率 = 最终决策与真值一致的冲突数 / 带真值冲突总数
能力保持率 = 边侧模型得分 / 云端模型得分
```

必须特别区分：运行时`resolution_success`表示系统是否形成稳定决策，不等于决策正确；比赛的
仲裁成功率只有在存在真实标签时才能计算。

### 2）必要基线

至少对比以下方案：

1. 全边缘；
2. 全云端；
3. 固定比例分流；
4. 固定置信度阈值分流；
5. 固定Peer优先；
6. 最高置信度仲裁；
7. DREAM-CE完整方案。

### 3）消融实验

分别去掉动态阈值、节点可靠度、新鲜度、时空一致性和低共识云复核，观察平均/P95时延、弱网
业务保持率、冲突率和冲突解决成功率变化。只有DREAM-CE相较上述对照产生稳定增益，才能将
其作为经验证的创新点写入最终材料。

## 7. 当前创新性评价

### 已形成的创新点

1. **跨层联合决策：**把模型不确定性、任务风险、网络状态、节点负载和剩余deadline统一到
   同一个可解释代价函数中，而不是使用单一置信度阈值。
2. **证据化多边缘仲裁：**同时利用节点可靠度、观测新鲜度、时空一致性和模型版本，避免最高
   置信度节点直接支配结果。
3. **安全与实时性分离：**紧急动作本地立即执行；普通低共识冲突设计为进入云端复核。当前
   仲裁 API 会返回复核标记，自动云复核闭环尚待接入。
4. **真实指标口径：**将“成功返回结果”和“结果与真值一致”分开统计，避免形成虚假的仲裁
   成功率。
5. **跨场景统一接口：**工业视觉、交通轨迹以及后续能源场景只替换感知适配器，调度和仲裁
   层保持一致。

### 当前不足

- DREAM-CE属于在现有技术基础上的组合与改进，是否构成有竞争力的创新必须依靠消融实验；
- 路由代价中的权重目前是可解释初值，尚未通过真实运行数据拟合；
- 节点可靠度目前由配置输入，尚未实现滑动窗口在线更新；
- 工业视觉和交通感知模型尚未接入，冲突样本也没有真实标签；
- 边侧大模型是否能在1.5GB内达到80%至90%能力仍未知。
